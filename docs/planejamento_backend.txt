PLANEJAMENTO BÁSICO DO BACKEND

Objetivo: construir uma API RESTful em Node.js + TypeScript + Express, integrada ao Supabase/PostgreSQL, responsável por autenticação de doadores e funcionários, cadastro de hemocentros, controle de estoque de sangue, ingestão de dados IoT, geração de alertas, notificações, histórico de doações e relatórios estatísticos para o dashboard web e o aplicativo mobile.

Arquitetura: front-end React e mobile React Native consomem a API. A API valida JWT do Supabase, aplica regras de autorização por perfil e acessa o PostgreSQL/Supabase. O ESP32 envia leituras de ambiente e balança para endpoints IoT autenticados por chave. O backend grava leituras, chama funções RPC do banco para processar balança, previsão, média de doações, estudo de doadores e CEP. As funções SQL existentes serão reaproveitadas, mas corrigidas e documentadas.

Módulos previstos: autenticação/perfil do doador; hemocentros e estoque; sensores e IoT; alertas; notificações e campanhas; doações e histórico; relatórios estatísticos; dashboard; administração de funcionários. Cada módulo terá rotas, schemas de validação, controllers/services e documentação OpenAPI.

Segurança: JWT do Supabase para usuários; service role key apenas no backend; RLS no banco; header `x-iot-key` para dispositivos; validação de payload com Zod; Helmet e CORS; variáveis de ambiente; separação entre rotas públicas, rotas de doador, rotas de funcionário e rotas IoT.

Banco: corrigir o script com `doacoes`, `update_updated_at`, triggers de estoque, RLS, tabela de campanhas/conquistas se necessário, seeds e índices. Manter PostgreSQL/Supabase como base principal. Usar as RPCs `processar_leitura_balanca`, `previsao_demanda_sazonal`, `relatorio_media_doacoes`, `relatorio_estudo_doador` e `relatorio_cep` como camada de cálculo estatístico.

Entregas por etapa: primeira etapa, correção do banco e API base com health check, auth e `/me`; segunda, hemocentros, estoque e sensores; terceira, IoT ambiente e balança; quarta, alertas e notificações; quinta, doações e histórico; sexta, relatórios estatísticos e dashboard; sétima, OpenAPI completo, integração com React/mobile, seeds, testes e vídeo de demonstração.

Critérios de aceite do 4º semestre: API RESTful funcional, documentada em OpenAPI, integrada ao banco relacional, recebendo dados IoT simulados ou reais, fornecendo dados para dashboard web e mobile, com funções estatísticas expostas e versionamento no GitHub com commits de todos os integrantes.
